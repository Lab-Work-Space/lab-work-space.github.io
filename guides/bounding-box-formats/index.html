YOLO, COCO and Pascal VOC bounding boxes

The three common detection formats describe the same rectangle with four numbers each, and the numbers mean different things. A converter that gets one convention wrong still produces a valid file, which is why the mistake can go unnoticed until a weak result after training. This guide sets out the conventions, writes one box in all three, and gives plain Python to convert it in both directions.

The conventions

Four numbersx centre, y centre, width, heightx and y of the top-left corner, width, heightxmin, ymin, xmax, ymax

The Pascal VOC development kit counts pixels from 1 and includes both end pixels, so a box over the first 100 pixels of a row is xmin 1 and xmax 100. Many tools that write VOC files count from 0 instead.

One box in all three formats

Take an image 640 pixels wide and 480 high, and a box covering pixels 100 up to 300 across and 80 up to 280 down. It is 200 pixels wide and 200 high. In the three formats:

  • YOLO: 0 0.312500 0.375000 0.312500 0.416667, where 0 is the class id.
  • COCO: "bbox": [100, 80, 200, 200], with "category_id" beside it.
  • Pascal VOC: xmin 101, ymin 81, xmax 300, ymax 280, counting from 1.

The conversion

Each function takes one box as a list. The image size is needed only for YOLO. The script below converts the example from YOLO to COCO to VOC and back, and prints the largest error in pixels:

python3 - <<'PY'
def yolo_to_coco(box, W, H):
    xc, yc, w, h = box
    return [(xc - w / 2) * W, (yc - h / 2) * H, w * W, h * H]

def coco_to_yolo(box, W, H):
    x, y, w, h = box
    return [(x + w / 2) / W, (y + h / 2) / H, w / W, h / H]

def coco_to_voc(box, one_based=True):
    x, y, w, h = box
    d = 1 if one_based else 0
    return [x + d, y + d, x + w, y + h]

def voc_to_coco(box, one_based=True):
    xmin, ymin, xmax, ymax = box
    d = 1 if one_based else 0
    return [xmin - d, ymin - d, xmax - xmin + d, ymax - ymin + d]

W, H = 640, 480
yolo = [0.3125, 0.375, 0.3125, 0.416667]
coco = yolo_to_coco(yolo, W, H)
voc = coco_to_voc(coco)
back = coco_to_yolo(voc_to_coco(voc), W, H)
error = max(abs(a - b) * s for a, b, s in zip(yolo, back, (W, H, W, H)))
print("yolo", " ".join(f"{v:.6f}" for v in yolo))
print("coco", [round(v, 1) for v in coco])
print("voc ", [round(v, 1) for v in voc])
print(f"round trip error: {error:.3f} px")

voc  [101.0, 81.0, 300.0, 280.0]
round trip error: 0.000 px

The flag one_based is the Pascal VOC trap in one argument. For a tool that writes VOC counting from 0, call both VOC functions with one_based=False.

The traps

  • Pascal VOC counted from 0 or from 1. Read one file you know and compare it with the image: a box on the first pixel row has ymin 1 in the original convention and ymin 0 in the other. Mixing them moves every box by one pixel, which does little to a large box and a lot to a small one.
  • COCO category ids with gaps. The official COCO 2017 annotations number their 80 classes with ids from 1 to 90. YOLO wants a class id that is the position in a list starting at 0. Sort the ids from categories and number them in order; never subtract 1.
  • YOLO rounding on small boxes. A label file holds decimals, and few decimals are not harmless on a small box. A box 3 pixels wide on a 640 pixel image:
python3 - <<'PY'
W = 640
for decimals in (3, 4, 6):
    stored = round(3 / W, decimals)
    px = stored * W
    print(f"{decimals} decimals: 3 px is stored as {stored} = {px:.2f} px")
PY
3 decimals: 3 px is stored as 0.005 = 3.20 px
4 decimals: 3 px is stored as 0.0047 = 3.01 px
6 decimals: 3 px is stored as 0.004687 = 3.00 px

Write at least six decimals.

  • Images with an EXIF orientation. Many viewers turn a photo that carries an orientation tag, while its stored width and height, and the labels made on the stored pixels, stay as they were. Then the labels fit the pixels but not what you see, or the other way round. Labelfence reports it as W_IMAGE_EXIF_ORIENTATION; the fix is to apply the rotation to the pixels and drop the tag.

Whole datasets

A script like the one above is enough for a few boxes. For a whole dataset the work is the loop around it: reading every file, mapping class ids, writing the result and checking it. The full edition of Labelfence converts whole datasets between YOLO, COCO and Pascal VOC, and reads the result back and compares it with the source before it writes; it costs 29 USD: Labelfence on Gumroad.
