How to check a YOLO dataset before training

A training run on a detection dataset can take hours, and a bad label does not stop it. This guide lists what usually goes wrong in a YOLO dataset, then walks through a free audit that lists those problems in one pass and exits with a code your scripts can test.

Before you start. The commands below need the free lite edition of Labelfence. The install is described on the Labelfence page; it needs Python 3.10 or newer and git, and you run this line inside a virtual environment:

pip install "git+https://github.com/Lab-Work-Space/labelfence-lite@v1.0.0"

What goes wrong in practice

  • A label file has no image, or an image has no label file. Renaming or filtering one folder and not the other is a common cause.
  • A class id is at or above nc, the class count in data.yaml, or it is negative or not a whole number.
  • A box lies partly or wholly outside the image, so one of its four numbers is below 0 or above 1.
  • A label line has the wrong number of fields. Every line needs exactly five: class, x centre, y centre, width, height.
  • A label file is empty, or holds the same box twice.
  • There is no validation split, so the numbers you read after training are measured on nothing.

The format and the rules behind each of these are in the guide to the YOLO label format.

Ultralytics reports many label problems as warnings while it builds its cache. A warning in the middle of a long training log is easy to miss, and it tells you about the files it met, not about the dataset as a whole. An audit before training gives you the full list in one place.

Audit a dataset

To follow along without your own data, Labelfence writes a small synthetic dataset that holds one example of every code the lite edition reports:

labelfence sample --out demo --case faulty

Audit it. The command prints a summary and the findings grouped by code, and writes demo-audit.json next to where you ran it:

labelfence audit demo

Part of what it prints:

Labelfence 1.0.0: demo
Format: yolo (layout: ultralytics)
Images: 23  Boxes: 91  Classes: 4
Findings: 9 errors, 12 warnings
  E_LABEL_MALFORMED: 1
  W_SPLIT_MISSING: 1

The first lines say what it read: the layout it detected, how many images and boxes, and how many classes data.yaml declares. The Findings line counts errors and warnings. Codes starting with E_ are errors and codes starting with W_ are warnings. Below the summary, every code gets a heading, a count and the first files and lines it was found in.

On a dataset with errors the exit code is 3. That is the signal, and it is the expected result here.

Fix by code

Start with the errors, then read the warnings and decide which matter for your data.

CodeWhat it meansWhat to do
E_LABEL_MISSING_IMAGEA label file has no imageRestore the image or delete the label file
E_LABEL_MALFORMEDA line has the wrong field count or a non-numeric fieldOpen the file at the line shown and correct it
E_CLASS_ID_INVALIDA class id is not below the class countFix the id, or the class list in data.yaml
E_BOX_OUT_OF_RANGEA box value is outside 0 to 1Clip the box to the image, or re-export the labels
E_IMAGE_UNREADABLEThe image header is missing or cut off, or the file is not an imageReplace the file
W_LABEL_EMPTYA label file has no boxesFine for a background image; otherwise label it
W_SPLIT_MISSINGThere is no validation splitCreate one before you trust any metric

Other codes and fixes are in the guide to the YOLO label format. Labelfence never changes your dataset, so fixing is your decision. Run the audit again after each round of changes.

Use it in CI

--strict turns warnings into exit code 3 as well, and --quiet prints the summary only. A clean dataset passes, and the faulty one does not:

labelfence sample --out clean --case clean
labelfence audit clean --strict --quiet --report clean.json > /dev/null 2>&1
echo "clean: exit code $?"
labelfence audit demo --strict --quiet --report strict.json > /dev/null 2>&1
echo "demo: exit code $?"
clean: exit code 0
demo: exit code 3

In a CI job the line to add is labelfence audit path/to/dataset --strict --quiet --report audit.json. A step that exits with 3 fails the job, and the JSON report is there to attach as an artifact. The other exit codes are 2 for a usage error and 5 for input that is not a dataset.

Look at the balance

labelfence stats prints counts per split and per class without running the checks:

labelfence stats demo
Labelfence 1.0.0: demo
Images: 23  Boxes: 91  Classes: 4
  class 0 cat: 76 boxes (83.5%)
  class 3 fish: 0 boxes (0.0%)

A class with almost no boxes, or none, shows here before it shows up as a weak result after training. The audit raises it as W_CLASS_IMBALANCE and W_CLASS_UNUSED.

What the lite edition leaves out

The lite edition reads YOLO datasets only, and it does not look for images that appear in more than one split. If your data is in COCO or Pascal VOC format, or you suspect look-alike images on both sides of the train and validation split, the full edition adds both, and costs 29 USD: Labelfence on Gumroad.
