The YOLO label format, and the errors that break it

A YOLO label is a plain text file with one line per box. The format is short enough to learn in a minute, and many errors in a dataset are a line that breaks one of its rules. This guide gives the rules, one worked example, and then each error with the code that Labelfence lite reports for it and the fix.

Before you start. The commands below need the free lite edition of Labelfence. The install is described on the Labelfence page; it needs Python 3.10 or newer and git, and you run this line inside a virtual environment:

pip install "git+https://github.com/Lab-Work-Space/labelfence-lite@v1.0.0"

The format

Each image has a label file with the same base name and the extension .txt. In the Ultralytics layout, images/train/cat1.jpg has the label labels/train/cat1.txt. An image with no boxes has an empty label file or none at all. Every line holds five numbers separated by single spaces:

FieldMeaningAllowed values
1Class idA whole number from 0 to nc minus 1
2x centre of the box0 to 1, as a fraction of the image width
3y centre of the box0 to 1, as a fraction of the image height
4Width of the boxAbove 0, up to 1, as a fraction of the image width
5Height of the boxAbove 0, up to 1, as a fraction of the image height

The class names live in data.yaml, in nc and names. The label file holds only the id, which is the position of the name in that list, counting from 0.

A worked example

Take an image 640 pixels wide and 480 high. A cat is in the box whose left edge is at x 100, top edge at y 80, right edge at x 300 and bottom edge at y 280, all in pixels. The box is 200 pixels wide and 200 high. Its centre is at x 200 and y 180. Divide the x values by 640 and the y values by 480:

python3 -c '
W, H = 640, 480
left, top, right, bottom = 100, 80, 300, 280
xc, yc = (left + right) / 2 / W, (top + bottom) / 2 / H
w, h = (right - left) / W, (bottom - top) / H
print(f"0 {xc:.6f} {yc:.6f} {w:.6f} {h:.6f}")
'
0 0.312500 0.375000 0.312500 0.416667

That line goes into the label file with class id 0. Six decimals are enough: on a 640 pixel image the rounding is below a thousandth of a pixel.

How a line breaks

Labelfence lite ships a synthetic dataset where every kind of error is present once. These commands write it and show line 2 of five of its label files:

labelfence sample --out demo --case faulty
for f in malformed outofrange badclass degenerate duplicate; do
  echo "$f:"; sed -n 2p demo/labels/train/$f.txt
done
malformed:
0 0.5 0.5 0.2
outofrange:
0 0.5 0.5 1.2 0.2
badclass:
7 0.5 0.5 0.2 0.2
degenerate:
0 0.5 0.5 0.0 0.2
duplicate:
0 0.288660 0.539683 0.164948 0.412698

The first has four fields, the second a width of 1.2, the third a class id 7 in a dataset of four classes, the fourth a box with no width. The fifth repeats line 1. The audit names each of them, together with the others in the sample; these are some of its lines:

labelfence audit demo
E_BOX_DEGENERATE (1): a box has no positive width or height
E_BOX_OUT_OF_RANGE (1): a box value is outside the image or outside 0 to 1
E_CLASS_ID_INVALID (1): a class id is not an integer, is negative, or is at least the class count
E_DUPLICATE_BOX (1): a file holds two boxes with identical class and coordinates
E_LABEL_MALFORMED (1): a label line has the wrong field count or a non-numeric field
E_LABEL_MISSING_IMAGE (1): a label file has no image
E_NAMES_MISMATCH (1): the category names disagree with the class list
W_BOX_NEAR_DUPLICATE (1): two boxes of one class overlap almost completely
W_BOX_TINY (1): a box is smaller than the minimum size
W_IMAGE_WITHOUT_LABEL (1): an image has no label file (a background image)
W_LABEL_EMPTY (1): a label file has no boxes

Each error and its fix

CodeWhat is wrongFix
E_LABEL_MALFORMEDThe line does not have five fields, or a field is not a numberRewrite the line. A segmentation label has many more numbers, and the lite edition reads it as a box only with --allow-polygons
E_CLASS_ID_INVALIDThe class id is negative, not a whole number, or not below the class countCorrect the id, or add the class to names and nc
E_BOX_OUT_OF_RANGEA value is outside 0 to 1 (including a negative width), usually because pixels were written instead of fractions, or the box leaves the imageDivide by the image size, or clip the box to the image
E_BOX_DEGENERATEThe width or the height is 0. A negative value is reported as E_BOX_OUT_OF_RANGEDelete the line or redraw the box
E_DUPLICATE_BOXTwo lines are identicalDelete one
W_BOX_NEAR_DUPLICATETwo boxes of one class overlap almost completely: IoU of 0.95 or moreKeep one, unless two real objects are stacked
W_BOX_TINYA side is under 2 pixels (change it with --min-box-px)Check whether it is a real object or a mis-click
E_LABEL_MISSING_IMAGEA label file has no image with the same base nameRestore the image, or delete the label
W_IMAGE_WITHOUT_LABELAn image has no label fileCorrect for a background image; otherwise label it
W_LABEL_EMPTYA label file has no boxesThe same: background image, or unfinished work
E_NAMES_MISMATCHThe class names in data.yaml disagree with the class list, for example a name is listed twiceMake names and nc agree, with one name per class

An error means the training code would misread or drop the line. A warning means the data may be fine, and the choice is yours.

Two checks by hand

You can test the most common error without any tool. A line whose second field is above 1 was almost certainly written in pixels:

printf '0 0.5 0.5 0.2 0.2\n0 320 240 128 96\n' > labels.txt
python3 - <<'PY'
for line in open("labels.txt"):
    if float(line.split()[1]) > 1:
        print("pixels, not fractions:", line.strip())
PY
pixels, not fractions: 0 320 240 128 96

The same idea extends to every rule in the table, and Labelfence applies all of them to every file, and to the images, in one pass.

When the labels come from another format

Labels exported from COCO or Pascal VOC need a conversion first, and the conventions differ in ways that produce the errors above. They are set out in the guide to bounding box formats.
