Near-duplicate images across train and val

A validation set is supposed to stand in for images the model has never seen. When a copy, or a near copy, of a training image is also in the validation set, the model is scored partly on what it has memorised, and the number says less than it appears to. This guide explains how that happens, gives a short script that finds exact copies, and says what it cannot find and what to use for that.

Before you start. The commands below need the free lite edition of Labelfence. The install is described on the Labelfence page; it needs Python 3.10 or newer and git, and you run this line inside a virtual environment:

pip install "git+https://github.com/Lab-Work-Space/labelfence-lite@v1.0.0"

How it happens

  • Video frames. Frames a fraction of a second apart are almost the same picture. Split the frames at random and most validation frames have a close neighbour in training.
  • Augment, then split. If flipped, cropped or colour-shifted copies are written to disk before the split, the copies of one photograph land on both sides.
  • Downloaded twice. The same picture collected from two searches, or from two sources, arrives under different file names and sometimes at different sizes.
  • Merged datasets. Two public datasets can share images, and each keeps its own split.

The cheapest defence is the split itself: split by source, such as by video, by session or by camera, never by single image. The rest of this guide is for checking a split that already exists.

A free check for exact copies

Two files with the same bytes have the same SHA-256 hash. The script below reads every image of a dataset, groups the files by hash, and reports the groups that appear in more than one split. To try it, make a dataset with a clean audit and put a copy of one training image, with its label, into the validation folder:

labelfence sample --out clean --case clean
cp clean/images/train/img_000.jpg clean/images/val/copy_of_img_000.jpg
cp clean/labels/train/img_000.txt clean/labels/val/copy_of_img_000.txt
labelfence audit clean --quiet --report clean.json
Findings: 0 errors, 0 warnings

The audit is clean, because the lite edition does not look for duplicate images. Now the script:

python3 - clean <<'PY'
import collections, hashlib, pathlib, sys

IMAGES = {".jpg", ".jpeg", ".png", ".bmp", ".tif", ".tiff", ".webp"}
root = pathlib.Path(sys.argv[1])
groups = collections.defaultdict(list)
for path in sorted(root.rglob("*")):
    if path.is_file() and path.suffix.lower() in IMAGES:
        groups[hashlib.sha256(path.read_bytes()).hexdigest()].append(path)

def split_of(path):
    parts = path.relative_to(root).parts
    return parts[1] if parts[0] == "images" and len(parts) > 2 else parts[0]

for paths in groups.values():
    splits = {split_of(p) for p in paths}
    if len(splits) > 1:
        print("identical bytes in", " and ".join(sorted(splits)))
        for p in paths:
            print(f"  {p.relative_to(root)}")
PY
identical bytes in train and val
  images/train/img_000.jpg
  images/val/copy_of_img_000.jpg

It finds the copy. For your own data, replace clean with the dataset folder. The script treats the first folder under images/ (or the top folder in the <split>/images/ layout) as the split name, and it reads every file once.

What exact hashes miss

Change one pixel, resize the picture or save it again as a JPEG, and the hash is completely different. Here is a 90 percent resize of the same image, compared with the original:

python3 - <<'PY'
import hashlib, io
from PIL import Image

original = open("clean/images/train/img_000.jpg", "rb").read()
image = Image.open(io.BytesIO(original))
new_size = (image.width * 9 // 10, image.height * 9 // 10)
smaller = io.BytesIO()
image.resize(new_size).save(smaller, "JPEG")

def digest(data):
    return hashlib.sha256(data).hexdigest()

print("same hash:", digest(original) == digest(smaller.getvalue()))
PY
same hash: False

To the eye it is the same picture. Pillow, used here, is installed with Labelfence.

Free tools for near-duplicates

FiftyOne has a brain module that computes similarity between images and can flag exact and near duplicates in a dataset. cleanvision is an open-source package that audits an image collection for problems such as blurry, dark or near-duplicate images. Both have open-source editions, and both fit when you are already working with those tools.

What the full edition does

The full edition of Labelfence computes perceptual hashes of every readable image and treats two images as near-duplicates when both hashes are close. It groups the images connected that way, raises a finding for every group whose images lie in two or more splits, and writes split lists in which each group stays together, so the problem does not come back with the next split. It costs 29 USD: Labelfence on Gumroad.

It finds copies that were resized, re-encoded, shifted in brightness or contrast, or turned to grayscale. It does not find crops, mirrored copies or rotated copies; a slightly cropped or rotated copy is sometimes matched, and you should not rely on it. Different frames from a fixed camera, or of a static scene, can form a group too, because the hashes compare the coarse look of a picture and not what is in it, so look at the members of a group before you decide. No detection rate is stated, because none was measured on your images.

When you find copies

Remove the copies from the validation set, not from training, and then split again by group so that the same pictures cannot return. Evaluate the model again afterwards, because any earlier validation number was measured on a set that included them. Keep a list of the files you moved, with the reason, so that the next person who rebuilds the dataset does not put them back by accident.

Whatever tool you use, report the split method together with the validation number: by source, by single image, or by group. A reader can then judge what the number can mean.
